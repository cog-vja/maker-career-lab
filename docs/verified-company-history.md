## スキーマと承認境界

`data/company-history/issuer-registry.json` は、EDINETコード、証券コード、照合時の社名、元書類、業種・分類の出典を保持する。決算実績は法人を識別する `edinet:E…` と期間開始・終了を使う。新しいEDINETコードの持株会社化、合併、証券コードの再利用は同一法人の履歴に足さない。月次は照合待ちとして従来の値を保持する。上場廃止企業の過去記録も残る。追加・削除を伴う掲載社変更は原本照合付きの登録簿移行を要する。

`data/company-history/releases/NNNNNN.jsonl` は1行目がスキーマ・観測・公開JSのSHA-256・直前のSHA-256、後続が変更行。数値は掲載と同じ単位（財務の金額は億円、給与は万円、比率は%）。財務範囲、給与範囲、会計基準は原行に保持し、営業利益率は売上が正の開示値を使う。各行の取得日時の欠損と、照合日・観測日・Cloudflare本番確認日は区別する。月次の観測日は決算期を変更しない。

新決算期・訂正報告書・解析処理の改訂は異なる `kind`。正式な訂正は書類種別130、新旧書類IDと原本リンクで示す。解析改訂は同一書類・原本ハッシュと公開レビュー根拠を要求する。過去実績は上書きせず、変更理由と直前の実績ハッシュを残す。同じ数値・書類に照合日等を追記すると、実績数は増えない。現行月次は訂正を自動反映せず報告に残す。正式な訂正や処理の修正は原本確認後に `stage-reviewed` で専用PRに添付する。現在の掲載期の訂正に対応し、過去の非掲載期だけの訂正の取り込みは今後の対象。

履歴はレビューPR内では候補で、承認された `main` に取り込まれたファイルだけを承認済み履歴とする。実際の配信はCloudflareで独立に確認する。月次の件数は `company-history-plan.json` で追跡する。採用変更のない実行や中断した取得の詳細は既存の90日成果物に残し、決算実績の追記やレビューPRは発生しない。採用があった月の公開可能な保留理由・書類IDは台帳にも記録する。取得エラーの例外文字列は台帳へ転記しない。

## 月次連携と復元

1. 現行のEDINET月次は **GitHub Actionsで手動無効**。設定上は毎月5日12:23 JSTで、次の枠は **2026年12月5日12:23 JST**。無効の間は起動しない。まず初期保存PRをレビューし、下記の復元とCIを確認する。実行状態の変更と最初のAPI付き実行は運営者が判断する。
2. 次回起動時は現在の `company-data.js` とアーカイブのSHAを照合してから既存の取得・6指標・公開ゲートを通す。EDINETの提出会社と財務範囲を既存データと照合する。保留企業の前回値を保ち、他社の合格分を継続する。
3. 同じ月次PRに検証済みJSと新規履歴ファイルを含める。連番ファイルは一時ファイルの検証後に排他的に作成し、既存ファイルの削除・変更はPRチェックで拒否する。同一候補の再実行、内容変更なし、失敗、拒否済みPRによって承認済みの履歴は増えない。別の候補が先に進んだ場合は最新mainから再生成する。
4. 復旧を確認するときは次のように作業ディレクトリ外に復元する。履歴の末尾または `--release N` を選べる。復元先を上書きしない。承認済みの `main` を採用し `git bundle create mcl-history.bundle refs/heads/main` でオフライン複製を保存できる。配信を一時的に戻すときはCloudflareの過去バージョンとGitの対応を記録し、アーカイブの過去実績を消さない。

```sh
python3 company_history.py verify
python3 company_history.py restore /tmp/mcl-restored-company-data.js
cmp company-data.js /tmp/mcl-restored-company-data.js
node --check /tmp/mcl-restored-company-data.js
python3 -m unittest -v test_company_history.py
```

月次結果を既に取得している場合は、通常の `stage-monthly` の引数に `--dry-run` を付けると書き込みなしで確認できる。手動訂正の場合は `stage-reviewed --candidate PATH --evidence PATH --commit COMMIT --dry-run`。証拠JSONは証券コードをキーに、訂正に `kind: amendment`、`edinet_code`、`document_type: "130"`、`document`、`supersedes_document`、`source` を使用する。解析見直しには `kind: processing_revision`、`edinet_code`、`source_sha256`、`review` を使う。報告書・6指標の確認はレビューで行う。
