# 企業比較の保存と再訪時の確認

比較結果の「この2社を保存」で1組をこのブラウザに保存する。「保存した比較」を開くと最新の決算期、平均年間給与、営業利益率を見られる。1社ずつの解除、比較候補への設定、最新データでの2社比較、全件削除ができる。別の比較を保存すると1組が入れ替わる。ウォッチリストと前回比較の復元は、同じ2社と同じ保存操作を使うため一つにまとめた。

既存の比較結果と収録企業一覧の折りたたみを参考に、比較ページ内に細い罫線とテキストの操作を置いた。保存した企業の判定には比較データの証券コードと提出会社名を使う。現在の掲載から消えた企業、同じコードの社名が変わった企業は解除でき、同一企業と確認できるまで復元を止める。保存にログインや追加通信が要らないため、履歴保存PRとは独立して使える。

## 表示と計測

- 保存時の給与・利益率と比較できる場合だけ、差分を表示する。会計基準・対象範囲・期長の違い、決算期の重なりは比較不可。新決算期、同じ決算期での書類の更新、同じ書類での掲載値の変更は表示上区別する。正式な訂正かは既存の出典欄で書類IDから原本を確認できる。照合日だけの更新では数値の変化を表示しない。
- 保存先は同一ブラウザの `localStorage`。ブラウザデータの削除、別ブラウザ・別端末への変更で引き継がれない。利用不可、容量不足、破損時も通常の企業比較を利用できる。保存内容と入力値は外部に送信しない。
- `company_comparison_save` は正常な保存・入れ替え、`company_comparison_restore` は復元による実比較、`company_watchlist_open` は保存ありの一覧を自分で開く操作、`company_watchlist_remove` は保存解除・全削除の操作。2社分の保存でも保存イベントは操作1回で1件。再読込、重複保存、保存失敗、破損データの削除では追加イベントを出さない。4イベントの共通パラメータは既存の `tool: company_check` のみ。

### 手元で再確認する

```sh
WORKERS_CI_BRANCH=main python3 cloudflare-build.py
python3 tests/test_pdca_smoke.py
node --test tests/analytics-events.test.cjs
python3 tests/check-saved-comparison-browser.py chromium
python3 tests/check-saved-comparison-browser.py webkit
```

ブラウザ試験はPlaywright Pythonと各ブラウザの事前インストールが必要。生成した `dist` を使い、サイトの同一オリジンとして応答を模擬し、GA4・A8を含む外部通信を遮断する。ロールバックは保存機能のPR単位で行い、既存の比較・広告設定と企業データを個別に編集せず復元できる。

## 公開後2〜4週間の評価

- 既存の週次PDCAでサイトマップから40記事が引き続き集計されることを確認する。比較ページは記事の集計範囲と分け、GA4の探索で `/company-check` とイベント名を使う。追加カスタムディメンションは不要。
- 比較ページの総ユーザー数と `company_compare_complete` の実数、各保存イベントの回数と利用ユーザー数を記録する。保存利用率は保存操作のユーザー数 ÷ 比較ページのユーザー数。登録ユーザー数は企業数と区別する。
- 保存一覧の利用ユーザー数と復元数を集計する。再訪の指標は同じ保存・復元が別セッションで確認できる場合に限り、読める母数とともに扱う。確認できない場合は復元数とGA4のリピーター実数を別々に記録する。
- 比較ページの広告クリックと比較完了件数を併せて記録する。短期間の比率変化から効果を断定せず、まず件数を並べる。公開前、計測の欠測、APIの集計遅延、受信確認後の0件を区別する。
- 公開後は実機のiPhone、実際のGA4受信、週次成果物の40件を確認する。ブラウザ試験時の計測はキューまでで、実際のGA4受信とA8の遷移・成果は評価対象外。
